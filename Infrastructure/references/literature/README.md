# Literature

This category holds papers, technical notes, codebooks, data dictionaries, and agent-generated summaries that inform analysis. It is the first category under [`Infrastructure/references/`](../README.md) and serves as the reference implementation of the category pattern documented there.

## Contents

| Path | Purpose |
|---|---|
| [`catalog.yaml`](catalog.yaml) | Machine-readable index of every literature entry. Agents read this for discovery; humans add entries via the intake playbook. |
| [`papers/`](papers/) | Saved research papers and technical notes (PDFs, preprints, working papers). |
| [`data_dictionaries/`](data_dictionaries/) | Schema docs, codebooks, and variable dictionaries for datasets used in analysis. |
| [`summaries/`](summaries/) | Concise extraction notes and summaries generated by agents (e.g., via [`/literature-intake`](../../commands/literature-intake.md)). |

## Operating Rule

When adding literature, always follow [`Infrastructure/commands/literature-intake.md`](../../commands/literature-intake.md) so the catalog stays complete, searchable, and consistent across contributors.

## Catalog Schema

`catalog.yaml` is a YAML document with the following shape:

```yaml
version: 1
last_updated: YYYY-MM-DD
entries:
  - id: <unique-slug>
    title: <full title>
    authors: [<author>, ...]
    year: <publication year>
    type: <paper | data_dictionary | summary | ...>
    path: <relative path from this file, e.g. papers/foo.pdf>
    added: YYYY-MM-DD
    verified: YYYY-MM-DD
    tags: [<tag>, ...]
```

Full schema rules are enforced by [`validate_literature_catalog.py`](../../scripts/validate_literature_catalog.py).

## Validation

Run after every catalog edit:

```bash
python3 Infrastructure/scripts/validate_literature_catalog.py
python3 Infrastructure/scripts/check_catalog_staleness.py
```

Both are invoked automatically by `make maintenance-check`.
